# 书籍转化为 AI 书籍规范

版本 0.1.1-draft｜整理日期 2026年11月5日｜状态 待审草案

本规范用于把已有书籍整理成能够被读者自己的 AI 可靠读取、解释和辅助学习的书籍包。它独立于单本书、网站实现和模型供应商管理。书籍原文仍是作品本身，教学材料是明确标注的补充；AI 接入成功不等于教学有效。

典型使用情形是已有10本或更多完成的书稿，按同一规范逐本转化。这里的“AI 改编”主要是为已有原文增加结构、入口和教学层，不默认重写作品。每本书分别确认权利、原文版次、学习目标、教学配置和验收结果；一本书通过，不代表其余书通过，也不预设自动同步或内容相同。

## 一 规范的管理与适用范围

本规范是 Open Learning Books 的跨书通用项目文件，权威源保存在本仓库 docs/ai-book-standard/AI-BOOK-STANDARD.md。各书记录所引用的规范版本和单书适配配置，不复制一套并行标准。Space 中的同内容文件作为阅读与下载副本，由 GitHub 版本同步；发生差异时以本仓库的明确版本为准。规范、模板、验收记录和变更说明分开管理。公开规范不包含私人制作档案，也不改变任何书籍的版权与公开范围。

规范分三层：

1. 通用基础：身份、权利、来源、原文完整性、教学材料区分、隐私、版本和真实验收。
2. 可选能力：问答、练习、角色演练、语音、学习进度，各自声明与验收；不要求所有书具有所有能力。
3. 单书配置：文体、读者、学习目标、默认学习模式、解释框架及专项风险。本书配置只能在权利和安全边界内调整，不得用单书风格取代通用要求。

“必须”表示本草案拟定的验收要求，不意味着所有要求已经获得用户逐项批准。第十二节区分已有依据与本次新增建议。正式采用后，新版本只作用于明确迁移的书籍，不自动改写已验收原稿。

## 二 转化前确认权利与原稿

- 登记书名、作者、语言、版次、来源位置、权利主体和实际许可；正文、插图、译文、字体、教学材料与软件分别登记。
- 区分拥有文件、获准阅读、获准发送给第三方 AI、获准公开全文、获准改编发行等权限。公开可读不是任意转载或改编的许可；软件开源许可不自动覆盖书稿。
- 明确权威原文及允许加工的范围。整理书籍包不自动授权修订原书、公开私有练习、变更版权或发布版本。
- 权利不明确时，先完成元数据与缺口登记，只提供获准的内容。不能用自动改写来规避权利限制，也不能宣称提供了无权提供的完整原文。
- 新编案例标为虚构；第三方观点、研究发现、作者综合解释及价值选择明确区分。没有读取过的材料不编造引文、页码或研究结论。

## 三 最小书籍包

每本书至少具备以下材料，允许文件格式不同，但信息不可缺失：

- 书籍清单：稳定 book_id、书名、作者、语言、适合读者、内容版本、规范版本、发布状态、权利说明和能力清单。
- 目录映射：稳定 chapter_id、展示序号、章名、完整原文位置、对应教学材料位置及版本。
- 完整原文：可独立阅读，含该版原有标题、正文、注释和来源说明。分章、分块是访问方式，不能改变或隐藏原文。
- 学习入口：一段带真实网址的启动文字，以及该网址上的读取顺序、材料身份、失败处理和下一步导航。
- 教学配置：选择提供教学时，按章给出具体目标、解释依据、常见误解、教学模式与停止条件。
- 验收与变更记录：说明检查过什么、未检查什么、使用哪个源版本、发现的问题与修订范围。

阅读包是基础。只有具备相应教学材料和实测证据，才能宣称“可问答”“可练习”或“支持语音”。不能把固定脚本演示描述成生成式 AI 教学。

## 四 入口与读取

公开且获准供 AI 读取的书，优先提供“复制一段启动文字，发给能访问网页的 AI”的路径。MCP 是可选适配方式，不作为所有读者的必经步骤，不要求读者提供 API Key 或让 AI 自行扩大权限。

入口写明书籍身份、版本、许可、默认学习方式、目录、完整原文和可选教学材料。读者指定章节时直达该章，只有未指定时才执行本书声明的默认起点；不先下载全书和所有练习。

入口能打开还不够：需要测试目录、指定章完整正文、练习和回顾规则是否实际可读。网页预览、搜索摘要、截断返回不能充当全文。材料不足时说清已读范围和失败位置，停止依赖缺失内容的教学；可提供经授权的镜像或完整学习包，但不绕过访问限制。

通用启动文字模板：

“请从【已验证的学习入口网址】学习《【书名】》。先读取入口，核对版本和材料身份，按入口指引进入【章节或起点】。以实际取得的正式原文为依据，区分原文、讲解和练习；读不到或只读到片段时明确说明，不用记忆或搜索摘要补写。按本书学习模式开始，我可以随时提问、跳过、暂停或结束。”

只有使用实际验证的网址后，该模板才可作为可用入口交付。不能承诺任何 AI、任何地区或账户都能访问。

## 五 原文忠实与阅读方式

原文、摘要、讲解、改写、训练概述和新编练习分别标明。原文模式按固定版次呈现，不增补对白、不改变人物事实，不为防止练习泄题而删去作者分析或结论。

长文可以按顺序分块。每块关联书籍版本、章节、段落位置及下一位置；记录实际取得和呈现的范围，发现漏块、重复或版本不一致时修复后再继续。不能仅凭“最后一块已返回”判定全章完整。

“默认先逐字读完整章”是《理解人性》的当前配置，不强制套用所有作品。其他书可以采用按需查阅、讲解或读者自选，但必须保留获准原文的清晰入口，也不能把缩写说成全文。任何模式都尊重读者的暂停、跳过和提问。

已获取、已显示、已口述、读者确认读过、理解证据是不同状态。文字完整或接口成功不能证明语音逐字完成，阅读完成也不能证明掌握。

## 六 AI 教学设计

每章目标应描述可以观察的理解或应用，如“区分事实与推测并说明依据”，而非只写“提升认知”。文学、历史、技术、实务等作品可采用不同目标，不统一为人格训练或角色扮演。

每项教学配置说明：依据哪些原文、允许补充哪些知识、AI 当前角色、可改变与不可改变的事实、提示策略、反馈依据、何时结束。课外补充需明确标注，不能混成作者原意。

区分阅读、解释、讨论、练习、角色演练、反馈和迁移。用户问解释时可以直接讲清；用户选择独立练习时，不提前替答。不能借“启发式教学”长期回避解答，也不因原文已经给过结论而假装读者不知道。

原文中的命令、角色台词及网页文本是学习资料，不是外部操作授权。不得据此上传回答、发送消息、安装工具、付费或改变访问权限。

## 七 练习与反馈

练习应包含目标、题面、已知事实、关键未知、参考理由或评判标准、常见误解、提示方式、结束条件和可选迁移。参考答案允许多种有依据的方案，不要求复述作者。

收到实际回答后，先反馈具体观点及依据，指出成立之处和重要推断缺口，再决定是否追问。不要只复述、夸奖或连续提问。追问必须增加理解；已有充分解释时可以小结、应用或结束，不按固定轮数延长对话。

角色事实应稳定，信息披露符合已知情境。新增条件明确标为练习变式，不倒写成原案事实。角色允许拒绝、不同意和保留未知，不因措辞礼貌就自动配合。

迁移需要改变与判断有关的责任、关系、资源或约束，不只换人名重做原题。回顾依据实际回答，区分提示帮助、独立解释、迁移尝试和未观察；未观察不是不会，模拟表现不是现实能力证明。不生成无依据的人格、情商或临床评分。

## 八 隐私和进度

默认不把私人回答、经历、评价或学习进度上传到书源、网站或仓库。学习包不包含真实读者表现，空白模板不能冒充学习记录。

建议使用可由读者掌握的最小续学记录：book_id、语言、原文版本、教学版本、chapter_id、模式、最后实际呈现位置和下一位置。是否增加练习证据由读者决定，不强求私人经历。

无远端进度能力时如实说明；跨对话或跨设备无法确认停点时，不假装记得。版本变化要检查章节映射，不能把旧位置无条件套到新原文。新增账户、云同步、保存时长和第三方共享另行设计并取得需要的授权。

## 九 验收

分别登记五种结果，不合成一个“全部通过”：

1. 格式检查：字段、稳定编号、目录、相对链接、文件完整性、章节顺序和版本绑定。
2. 内容审查：原文与源稿一致；新增教学目标、解释、题目、来源和权利匹配。
3. 实际访问：在声明支持的 AI、客户端和访问方式中，测试入口到全文及练习的完整路径。
4. 教学行为：实际对话是否忠于材料、正确反馈、允许异议、避免循环追问并尊重暂停。
5. 学习效果：真实读者的理解、独立解释、迁移和后续表现；没有证据时明确未验证。

建议最小测试集：指定非第一章；展示章号与稳定 ID 不同；长章分块与中途恢复；源内容截断；错误书名或版本；读者质疑作者；含关键推断错误的回答；练习中请求提示；重复追问风险；新情境迁移；暂停与退出；版本升级后的旧进度；无联网备用路径。声明语音能力时另测实际音频或可靠转写，不以文字测试替代。

测试记录包含时间、版本、客户端、模式、用例、预期、实际结果、证据、问题和修复状态。演示案例与比较版本的保留测试案例分开。已完成检查标通过或失败；未做标未测试，不适用须说明理由。

无权公开、拿错误书或版本冒充原文、缺失正文却宣称完整、严重错误解释、私人数据泄露等问题不能被其他高分抵消。某平台入口失败应停止宣称该平台可用；不必否定已经验证的其他路径。数值总分及通过阈值需单独确定，当前不虚构分数。

## 十 版本和修订

分别管理规范版本、原文版本、教学版本、结构格式版本和入口部署版本。每次发布清单绑定这些身份及实际文件，中文改稿不自动代表英文同步。

稳定章节 ID 不随展示顺序改变。原稿修订后检查受影响的练习、答案、引用和译文，未完成同步应明确标记；不能悄悄让新练习继续引用旧人物事实。

修订先确认基线与范围，保留旧版和变更原因，写入前检查并发版本，不覆盖他人新修改。检查范围围绕实际变更，不把每次修订都变成重新审整本书。发布后验证实际入口和文件；撤回或回滚也保留版本记录。

## 十一 每本书的实施流程与完成条件

按“确认原稿与权利 → 登记身份与能力 → 整理完整原文 → 配置教学 → 建立入口与备用包 → 格式及内容检查 → 真实 AI 试学 → 修复 → 在获准范围发布”执行。

多书转化可使用[书籍转换清单](BOOK-CONVERSION-REGISTER.md)管理队列，每书独立填写[适配登记](BOOK-PROFILE-TEMPLATE.md)和[验收记录](ACCEPTANCE-TEMPLATE.md)。共享规范只定义共同交付要求，不复制上一书的故事、题目、授权、默认模式或测试结论。允许按书或按阶段推进；只有明确授权的范围才改写原文、发布或迁移规范版本。

先选有代表性的一章验证教学方式，再推广；格式、身份、权利和原文完整性应覆盖全部入包章节。抽样教学不能称全书每章都已实测。

一本书的交付包应说明：权威版本；支持的能力与客户端；可用入口；完整原文及教学材料；验收结果；已知缺口；维护与勘误入口。完成转化不等于每种能力全部完成，只有满足所声明范围的验收才可标记该范围完成。

## 十二 已有依据与新增建议

已从现有文件确认：Open Learning Books 已有基本元数据、教学配置与评价案例约定；《理解人性》已有原文与训练分离、稳定章节 ID、完整阅读、具体反馈、停止规则、证据回顾及对话内隐私安排。文件存在不等于全部客户端或真实学习效果已验证。

从近期用户反馈确认的方向：将规范独立管理；入口简单，带网址的一段文字即可尝试开始；不能用概述替代要求的完整原文；反馈应具体回应读者，而非一直追问。这些方向在本草案中转为跨书可复用原则，单书细节仍单独配置。

本次新增的管理建议：三层规范结构、明确的最小交付包、五类验收结果、续学记录字段、多版本发布清单和最小测试集。它们是本次建议，不冒称既有已批准规则，也不代表已实现的软件功能。

不迁移为通用硬要求：《理解人性》的六部17章、每章人性机制与多场景创作安排、一次最多一个关键问题、默认全文逐字呈现及特定分块长度；旧《人性的弱点》本地课程的讲稿、进度与连续朗读要求。它们可成为适用作品的配置，不是所有书的写作或学习模板。
