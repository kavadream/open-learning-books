# 产品需求初稿

## 学习者流程

发现作品，了解适合人群和学习目标，阅读一个小节，完成合适的练习，获得具体反馈，在新情境中再次尝试，保存自己选择保留的学习记录。

首版原型已实现单作品阅读、选择反馈、脚本演练和设备本地记录。真实 AI、账户及跨设备同步属于后续里程碑。

## 创作者流程

确定读者与问题，描述可观察的学习目标，编写内容与来源，设计练习与角色，设置反馈标准，自己预览试教，邀请试读，修订后发布版本。

原型支持本地填写、预览、保存和 JSON 导出。后续编辑器应帮助非技术作者完成教学设计，避免要求作者自己编写系统提示词或实现计费。

## 平台与维护者流程

管理作品版本和发布状态，检查基本内容与教学质量，核对模型和语音使用，保护学习者记录，维护反馈和问题处理机制。对外公开的状态必须与真实实现一致。

## 首个真实 AI 试点的验收

- 每个练习有具体学习目标、角色背景、允许与不允许的教学行为。
- AI 使用服务端配置，能够区分本书内容与平台规则。
- 角色演练中事实和顾虑保持一致，反馈能指出对话依据。
- 允许合理分歧，不把顺从当作唯一成功结果。
- 失败、重试、取消、额度不足和服务未连接有清楚的用户提示。
- 记录真实调用和成本，不将演示额度作为付费余额。
- 测试不止看回答是否顺畅，还看是否支持读者独立完成新任务。

## 非功能要求

手机和电脑可用，支持键盘操作和可读的字号。客户端不能获得模型密钥。用户生成文字需要按文本安全显示。学习者能知道哪些记录只在本机、哪些会上传，以及谁能看到。

## 试点指标

观察有效练习完成情况、陌生情境判断表现、延迟后的独立使用、真实付费意愿、创作者完成首个合格小节所需时间，以及每次有效学习的服务成本。目标值应由试点数据确定。
