# 产品需求初稿

## 学习者流程

发现作品，了解适合人群和学习目标，阅读一个小节，完成合适的练习，获得具体反馈，在新情境中再次尝试，保存自己选择保留的学习记录。

首版原型已实现单作品阅读、选择反馈、脚本演练和设备本地记录。真实 AI、账户及跨设备同步属于后续里程碑。

## 创作者流程

确定读者与问题，描述可观察的学习目标，编写内容与来源，设计练习与角色，设置反馈标准，自己预览试教，邀请试读，修订后发布版本。

原型支持本地填写、预览、保存和 JSON 导出。后续编辑器应帮助非技术作者完成教学设计，避免要求作者自己编写系统提示词或实现计费。

## 平台与维护者流程

管理作品版本和发布状态，检查基本内容与教学质量，核对模型和语音使用，保护学习者记录，维护反馈和问题处理机制。对外公开的状态必须与真实实现一致。

## 首个真实 AI 试点的验收

- 每个练习有具体学习目标、角色背景、允许与不允许的教学行为。
- AI 使用服务端配置，能够区分本书内容与平台规则。
- 角色演练中事实和顾虑保持一致，反馈能指出对话依据。
- 允许合理分歧，不把顺从当作唯一成功结果。
- 失败、重试、取消、额度不足和服务未连接有清楚的用户提示。
- 记录真实调用和成本，不将演示额度作为付费余额。
- 测试不止看回答是否顺畅，还看是否支持读者独立完成新任务。

## 非功能要求

手机和电脑可用，支持键盘操作和可读的字号。客户端不能获得模型密钥。用户生成文字需要按文本安全显示。学习者能知道哪些记录只在本机、哪些会上传，以及谁能看到。

## 试点指标

观察有效练习完成情况、陌生情境判断表现、延迟后的独立使用、真实付费意愿、创作者完成首个合格小节所需时间，以及每次有效学习的服务成本。目标值应由试点数据确定。

## 已批准的推进计划（0.3.0-dev）

统一遵循 [AI 书籍包与分层验收规范 1.0.0](TEACHING_SPEC.md)，不为单本书另建平台标准，也不把其文风或角色练习强加给其他作品。

第一阶段实施闭环：手机尺寸浏览器打开本地预览 → 在书架选择版本 → 连续阅读完整篇章 → 按需提问/一次角色演练/有原话依据的自查 → 关闭教学继续阅读 → 刷新后恢复本机位置。现阶段问答和演练使用明确的脚本；不能因此宣称真实教学验收完成。

本阶段包含：协议校验、固定公开多章样例加载、篇章目录/连续正文/上下章切换、按书/版本分开的本机进度与思考、稳定 ID 位置恢复、浏览器私有导入、导入失败不污染现有数据、可选教学入口按书/章/版本绑定、三层状态贯穿 UI 和导入报告。

私有导入只在浏览器校验与保存，正文和学习记录不进入 Git、日志或公开上传接口；实际演示只能使用合成/公开测试材料。未经具体授权不把私有书稿交给真实模型。同一版本冲突拒绝静默覆盖；新版本独立保存，用户可显式沿用仍存在的小节位置，不复制已读或思考。

第二阶段需先补真实供应商/模型/合法项目配置和调用/费用上限授权，再做小范围模型与读者测试、有证据的教学反馈及失败用量验证。可信内容/授权审查、正式入库/版本发布也需要独立流程与权限；入库不代表通过，发布需另有决定。

账户跨设备、媒体/语音、持久对话、支付/代币继续后置。未部署到公网时，不声称用户手机已能公开访问；响应式模拟、离线测试、内容审查和真实教学试验分别记录。
